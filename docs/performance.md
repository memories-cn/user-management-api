# 性能测量

> **口径说明**：本文中的数字是**在开发机上测得的结果**，不是生产容量承诺。
> docs/TDD.md 12.1 的性能目标是首期工程目标，需在目标部署环境压测验证；
> PRD 风险表也明确要求"性能与并发指标不得被误读为已达成承诺"。
> 换环境（尤其是数据库位置：本地容器 vs 独立 RDS）后必须复测。

## 测量方法

两层测量，分别对应 docs/TDD.md 12.1 的两个目标：

| 目标 | 测量方式 | 命令 |
| --- | --- | --- |
| 纯本地授权决策 P95 ≤ 10 ms | Casbin 裸判定微基准（无 HTTP、无 DB） | `make bench` |
| 常规业务 API P95 ≤ 200 ms | 端到端 HTTP 负载测试（100 并发） | `IAM_LOAD_TEST=1 go test ./tests/integration/... -run TestLoad -count=1 -v -timeout 30m` |
| 单实例 ≥ 100 并发 | 同上（负载测试固定 100 并发 worker） | 同上 |

负载测试默认**不运行**（未设 `IAM_LOAD_TEST=1` 时 skip）：它需要 Docker，
且结果受机器负载影响很大，放进常规 CI 只会让流水线变慢并产出无意义的数据。
微基准进 CI，用于防止判定路径发生数量级级别的劣化。

## 复现环境

测量时的机器规格（复测时请更新本节）：

- CPU：Apple M 系列（11 核，`-11` 后缀）
- 内存：未单独限制
- PostgreSQL：`postgres:16-alpine` 容器，与 API 同机
- 服务：未限制容器资源

**注意**：数据库与 API 同机会显著低估延迟。生产若使用独立数据库，
网络往返会计入每一次查询，P95 会明显上升。

## 测量结果

### 纯本地授权判定（微基准）

```
go test ./internal/adapters/casbin/ -run '^$' -bench BenchmarkEnforce -benchtime=2000x
```

| 场景 | ns/op | B/op | allocs/op |
| --- | --- | --- | --- |
| 命中（user → owner 角色继承） | 5171 | 2001 | 34 |
| 未定义权限（默认拒绝） | 3861 | 1793 | 27 |
| 跨租户（不得命中） | 3136 | 1732 | 23 |
| 未知用户 | 3598 | 2015 | 34 |

对照目标 10 ms（= 10 000 000 ns）：**有约 1900 倍余量**。
这说明授权判定本身不是瓶颈——端到端延迟主要来自数据库往返与 HTTP 栈。

### 端到端 HTTP（100 并发）

| 场景 | 吞吐 | P50 | P95 | P99 |
| --- | --- | --- | --- | --- |
| `POST /api/v1/authorize` | 9570 req/s | 9.18 ms | 19.65 ms | 29.54 ms |
| `GET /api/v1/tenants/:id/members` | 4237 req/s | 22.14 ms | 37.56 ms | 47.15 ms |

两个场景均 0 失败，且 P95 均低于 200 ms 目标。
成员列表明显慢于授权判定，因为它要做成员查询 + 计数两个 SQL 往返。

### 多实例策略一致性窗口

由 `TestSecurity_MultiInstancePolicyConsistencyWindow` 实测：
传播耗时 **101.67 ms**（刷新间隔 100 ms）。

机制保证的上界就是**一个刷新间隔**：版本号 + 轮询决定了其他实例
最多滞后 `POLICY_REFRESH_INTERVAL`（生产默认 5s）。

需要区分两类撤权时效：

| 撤权类型 | 时效 | 原因 |
| --- | --- | --- |
| 成员移除、成员停用、租户停用 | **立即** | 租户守卫每次请求直查数据库，不依赖策略缓存 |
| 角色权限矩阵变更 | ≤ 一个刷新间隔 | 走 Casbin 内存策略，需等待版本号比对 |

## 何时需要复测

- 改变 `POLICY_REFRESH_INTERVAL` 或 Casbin 策略规模后
- 部署目标环境与本文"复现环境"不同（尤其是数据库位置）
- 单租户成员数或角色数上升一个数量级后（策略重载成本随之上升）
- 准备对外承诺容量数字之前
